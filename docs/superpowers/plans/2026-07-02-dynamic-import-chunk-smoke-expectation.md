# Dynamic-Import Chunk Smoke Expectation Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the 13 failing browser-bundle dynamic-import chunk smoke tests green by updating the shared harness's stale `0n` expectation to the real chunk value `7n`.

**Architecture:** Test-only change. One shared helper, `assert_browser_bundle_dynamic_import_loader` in `crates/kali_cli/tests/runtime_smoke.rs`, generates a node harness script that dynamically imports a compiled wasm chunk and asserts its `lazyValue()` result. All 13 callers write the chunk fixture `export function lazyValue() { return 7; }`; the helper still pins `0n` from the era when chunk bodies compiled to stubs returning the i64 default 0. We update the pinned value (and the matching stdout assertion) in that one helper.

**Tech Stack:** Rust integration tests (`cargo test`), node ESM harness scripts generated by `kali_runtime::browser_bundle_harness_script`.
